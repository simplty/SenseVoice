# /improve_prompt

**用于改进 ASR 文字纠错的 LLM 提示词的自定义命令**

## 描述
当发现 ASR 文字纠错效果存在问题时，使用此命令记录问题并自动优化 `.env` 文件中的 `LLM_SYSTEM_PROMPT` 和 `LLM_USER_PROMPT`。该命令会完成问题记录、提示词备份、冲突分析、自动改进、实际测试验证等一系列工作。

## 用法
```
/improve_prompt "ASR纠错问题描述"
```

## 示例
```
/improve_prompt "ASR经常把'机器学习'识别为'积极学习'"
/improve_prompt "专业术语'API接口'总是被纠正成'A批接口'"
/improve_prompt "中英文混合文本的标点符号处理不准确"
/improve_prompt "语音中的'Claude Code'经常被识别为'Cloud Code'"
```

## 目标对象
此命令专门用于优化以下两个ASR文字纠错提示词：
- **LLM_SYSTEM_PROMPT**: 定义ASR纠错助手的角色和任务
- **LLM_USER_PROMPT**: 具体的纠错指令模板（包含{text}占位符）

## 执行步骤

当执行此命令时，Claude Code 将自动完成以下工作：

### 1. ASR问题记录与分类
- 在 `.prompt_issues_log.md` 中记录ASR纠错的具体问题
- 自动分类问题类型：专业术语、标点符号、语法问题、同音异义词、特定词汇
- 添加时间戳和严重程度评估
- 问题ID自动递增以便追踪

### 2. 当前提示词备份
- 备份当前的 `.env` 文件为 `.env.backup_YYYY-MM-DD_HH-MM-SS`
- 特别保护 `LLM_SYSTEM_PROMPT` 和 `LLM_USER_PROMPT` 的当前值
- 记录备份原因和问题描述

### 3. 历史问题冲突分析
- 读取历史ASR纠错问题记录
- 分析新问题与已解决问题的潜在冲突
- 确保新的改进不会破坏已修复的ASR纠错规则
- 生成冲突风险评估（高/中/低）

### 4. ASR纠错效果分析
- 分析当前System Prompt的角色定义完整性
- 评估User Prompt的指令清晰度和格式规范
- 检查特殊纠错规则的覆盖范围
- 分析{text}占位符的使用效果

### 5. 生成纠错改进方案
基于以下因素生成具体改进建议：
- ASR问题的具体类型和场景
- 历史纠错经验和规则
- System Prompt 和 User Prompt 的最佳实践
- 特定领域的专业术语处理

### 6. 应用改进到.env文件
- 更新 `LLM_SYSTEM_PROMPT` 中的角色定义和纠错规则
- 优化 `LLM_USER_PROMPT` 中的指令格式和特殊处理
- 确保引号转义和格式正确性
- 保持{text}占位符的功能完整性

### 7. 实际ASR测试验证
- 使用改进后的提示词调用配置的LLM模型
- 准备包含已知问题的测试ASR文本
- 调用实际的纠错API进行测试
- 收集纠错结果用于效果评估

### 8. 自我评估纠错效果
- 分析测试结果：原问题是否得到解决
- 检查是否引入新的纠错错误
- 评估纠错的准确性、一致性和覆盖范围
- 对比改进前后的纠错质量

### 9. 迭代改进纠错规则
- 如果纠错效果不理想，基于测试反馈进行2-3轮优化
- 每轮改进针对具体的纠错问题调整提示词
- 特别关注专业术语和特定场景的处理

### 10. 展示纠错效果对比
- 展示改进前后的ASR纠错结果对比
- 说明解决了哪些具体的ASR识别问题
- 显示纠错准确率的提升情况
- 让用户确认纠错效果是否满意

### 11. 记录ASR改进历史
- 在 `.prompt_improvement_log.md` 中记录完整改进过程
- 包含：问题描述、修改的提示词、测试结果、纠错效果
- 记录迭代次数和每次改进的具体内容
- 为后续ASR问题提供参考依据

## ASR问题分类
- **terminology**: 专业术语识别问题
- **punctuation**: 标点符号处理问题  
- **mixed_language**: 中英文混合文本问题
- **homophones**: 同音异义词问题
- **specific_words**: 特定词汇纠正问题
- **grammar**: 语法结构问题

## 当前ASR纠错配置分析
根据您的 `.env` 文件，当前配置：
- **System Prompt**: 已定义专业的ASR纠错助手角色，包含Claude Code专门处理规则
- **User Prompt**: 使用{text}占位符，有明确的纠错指令
- **特殊规则**: 已包含Cloud Code → Claude Code的专门纠错规则

## 最佳实践
1. **具体描述问题**: 提供具体的ASR错误示例和正确结果
2. **测试多样性**: 改进后使用多种类型的音频测试
3. **监控副作用**: 确保新规则不影响其他正常识别
4. **定期回顾**: 查看改进日志了解纠错规则演化

## .env 配置要求
命令会读取和修改以下环境变量：
```bash
# 必需的LLM配置
LLM_ENABLED=true
LLM_API_KEY=your_key
LLM_MODEL=your_model
LLM_BASE_URL=your_url
LLM_TIMEOUT=3.0

# 将被优化的提示词
LLM_SYSTEM_PROMPT="..."
LLM_USER_PROMPT="..."
```

## 注意事项
- 命令会自动备份.env文件，可安全使用
- 测试验证使用当前配置的LLM模型
- 如果纠错效果不佳，会自动进行2-3轮迭代优化  
- 最终结果会展示ASR纠错对比，用户可选择是否接受改进
- 复杂问题如果多轮迭代后仍不满意，可从备份恢复

## 执行流程总结
1. 记录ASR问题 → 2. 备份.env文件 → 3. 冲突分析 → 4. 纠错效果分析 → 
5. 生成改进方案 → 6. 更新提示词 → 7. **ASR测试** → 8. **效果评估** → 
9. **迭代优化**(如需要) → 10. **展示对比** → 11. 记录归档
